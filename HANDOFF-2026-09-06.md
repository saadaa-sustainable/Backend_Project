## PR #37 — what's actually broken

The pipeline builds `ad_lifecycle` correctly to the rupee, then stops one table short. `/admin/analytics/ads-analyse` reads `FROM ad_performance_summary`, which was last refreshed 2026-08-28 (nine days stale as of the PR). Root cause: `refresh_ad_performance_summary` was registered only as a `FlattenJob` in `app/services/silver/registry.py`, and the in-process scheduler is off in prod (`SCHEDULER_ENABLED=false` on Render; GH Actions runs scripts, not the app). Identical defect to the one `ad_lifecycle` had earlier.

Fix adds `scripts/refresh_ad_performance_summary.py` (thin wrapper like `refresh_ad_lifecycle.py`), wires it into `refresh_all_daily.py` right after `ad_lifecycle`, and adds it to `meta-backfill.yml`. See the PR body for the reconciliation table.

**Structural note worth remembering:** being in the silver registry is not the same as being in the pipeline. Any new Gold table added the same way will need its own script wrapper too.
